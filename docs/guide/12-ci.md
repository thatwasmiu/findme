# 12. CI with GitHub Actions

CI ("continuous integration") runs the checks on GitHub's computers for every push, so a mistake is caught even if you
forget to run the tests. The workflow is `.github/workflows/ci.yml`.

## Step 1. Put the project on GitHub

1. On github.com: **New repository** → name `findme` → **Private** → do **not** add a README → Create.
2. In PowerShell, in the project folder (replace `YOUR-USER`):

```powershell
git remote add origin https://github.com/YOUR-USER/findme.git
git push -u origin main
```

`config/dev.json` and `config/prod.json` are never pushed (`.gitignore`). CI builds with `config/example.json`
(placeholder values: the app opens on "Config missing or invalid") unless you give it your dev config as a secret:

3. GitHub → repo → **Settings → Secrets and variables → Actions → New repository secret**: name `FINDME_DEV_CONFIG`,
   value = the whole content of your `config/dev.json`. From then on the APK and the `.ipa` CI builds point at your
   dev backend and can sign in. (The values are the same ones the web app ships to every browser, but keep them out
   of the repo like the rest of the config.)

## Step 2. Watch it run

GitHub → your repo → **Actions** tab. Each push starts a run with two jobs:

| Job | Runs on | When | Steps |
|---|---|---|---|
| **Check and build Android** | Ubuntu | every push and pull request | get packages → generated code up to date → format → analyze → tests with coverage → build the dev debug APK |
| **Build iOS (unsigned .ipa)** | macOS | pushes to `main`, or when started by hand | release build without signing, packed as `findme.ipa`: catches iOS-only breakage and gives you an app to sideload (you have no Mac) |

Downloads: open a finished run → **Artifacts** → `app-dev-debug-apk` (install on an Android phone),
`findme-unsigned-ipa` (a zip holding `findme.ipa`: sign and install it with Sideloadly, chapter 14 A2) and `coverage`.

Start the iOS job by hand: Actions → CI → **Run workflow**.

## Why iOS runs less often

On a private repo GitHub gives 2,000 free minutes a month, and **a macOS minute counts as 10**. An iOS build takes
10–20 minutes, so building iOS on every push would use the allowance in days.

## Reading a failed run

Click the red ✗ → the failed step → read the last lines.

| Failed step | Usually means | Fix locally with |
|---|---|---|
| Generated code is up to date | you changed a freezed class without regenerating | `dart run build_runner build -d`, commit |
| dart format | a file is not formatted | `dart format .`, commit |
| flutter analyze | a lint issue | `flutter analyze`, fix, commit |
| flutter test | a test fails | `flutter test`, read Expected/Actual |
| build apk / build ios | a native build problem | read the error; search it with "flutter" |
